## ما الذي أثبته اختبار Android فعليًا؟

الاختبار يحقن أحداث `MotionEvent` عبر `UiAutomation` إلى واجهة اللمس، ثم يتحقق من:

1. وصول كل زر (START، A/B/C، الاتجاهات الأربعة) إلى قناع الإدخال في المحرك.
2. زيادة عداد poll الخاص بالزر داخل JNI، وتغيّر RAM اللعبة استجابةً للمس.
3. **Multitouch**: الضغط المتزامن لليمين + B يصل إلى المحرك كقناع `RIGHT|B`، ثم تحرير B يبقي اليمين، ثم تحرير الكل يصفر الإدخال.
4. تبديل Bilinear بين `GL_LINEAR` و`GL_NEAREST` فعليًا في الـ renderer.
5. سحب مجموعة D-pad في وضع التحرير يغيّر موضعها ويصفّر الإدخال أثناء التحرير.
6. حفظ الحجم/الشفافية/الموضع/الفلتر، واستعادتها بعد `ActivityScenario.recreate()`.

التُقطت صور من داخل التطبيق أثناء التشغيل (شاشة اللعبة مع الأزرار، حالات الإدخال، الفلتر، ووضع تحرير Layout). الصور تحتوي على لعبة محمية بحقوق النشر ولذلك **لم تُضف إلى المستودع**.

## حدود التحقق وبيئة المحاكي

- لم يُجرَ اختبار على هاتف فعلي؛ النتائج أعلاه من محاكي x86 تحت TCG.
- بيئة المحاكي المحلية احتاجت تعديلات **للاختبار فقط** لتجاوز مشكلة تشفير في صورة API 28: صورة vendor منزوعة `forceencrypt`، ونسخة QEMU محلية عُطّل فيها خاصية التشفير. هذه التعديلات ليست جزءًا من التطبيق أو APK أو CI، ولا يجوز شحنها.
- لقطات الشاشة داخل الاختبار اختيارية (`-e screenshots true`) لأن المحاكي البطيء قد يتعثر عند التقاطها؛ التشغيل بدونها ناجح أيضًا.
- مفتاح debug المحلي ليس مفتاح توزيع نهائيًا. لم تُضف مفاتيح توقيع إلى Git.
- تشغيل GitHub Actions مستقل عن هذه النتائج؛ راجع صفحة Actions وArtifacts لكل دفعة.
